# 너랑나랑 마무리 흐름 검토 및 수정 1.6 — 2026-10-10

기준: 사용자 첨부 lib.zip 및 test.zip. 전체 Dart 소스와 31개 기존 테스트를 검토했다. 원본 백업 파일은 수정·설치 대상에서 제외한다.

## 확인된 결함과 연결
1. 동일 완료 ID 삽입은 기존 기록을 무조건 무시하고, 서명 화면은 저장소의 canonical 완료 기록을 먼저 조회하지 않았다. 로그에서 실제 저장 시각과 임시기록 시각 약8초 차이가 확인됐다. 시각 차이를 만드는 최초 경로는 실행 추적 없이는 확정할 수 없다.
2. GraceDraftRepository.save는 같은 ID의 오래된 화면 스냅샷도 무조건 덮어썼다. pendingRecord와 awaitingSignature가 후퇴할 수 있으며, 삭제 뒤 늦은 저장은 동일 세션을 부활시킬 수 있다.
3. 홈 resumeGrace는 Navigator.push의 종료를 기다리지만 은혜 화면이 pushReplacement로 교체되면 그 Future가 서명 완료 전에 끝날 수 있다. 홈 조회와 서명 저장·정리가 겹칠 수 있다.
4. 서명 저장, 확인, 질문 정리, 은혜 정리, 홈 이동을 하나의 실패로 표시했다. 성공적으로 저장된 기록도 정리 실패 때문에 저장 실패로 보였다.
5. 홈 읽기 요청이 겹치면 이전 조회 결과가 최신 결과를 덮어쓸 수 있다.
6. 기존 테스트는 Windows 플랫폼 override의 SharedPreferences 경로와 독립 서명 화면 중심이었다. Android SQLite와 홈→복원→서명→홈 전체 흐름에 공백이 있었다.
7. 앞선 패치에서 날짜 선후 검사까지 추가했으나 시스템 시각이 바뀌면 저장 완료를 막을 수 있었다. 콘텐츠 일치와 필수 서명 존재를 검증하고 기존 시각을 유지하도록 변경한다.

## 수정
- 저장소의 기존 완료 ID·내용을 우선 복구한다. 날짜는 최초 완료 기록 값을 유지하고 덮어쓰지 않는다. 이름·내용·장 등이 다르면 충돌로 보호한다.
- 최초 durable pendingRecord를 유지하고 이후 시도에서 재사용한다. 오래된 스냅샷이 서명 정보와 단계를 되돌리지 못한다.
- 정리 전에 마지막 완료 세션 ID를 SharedPreferences에 기록하여 같은 세션의 늦은 자동저장을 차단한다. 원문은 marker에 넣지 않는다. 키 하나만 저장하므로 매우 오래된 여러 세션 동시 실행에 대한 범용 tombstone 저장소는 아니다.
- 홈은 pendingRecord가 없어도 같은 완료 ID와 일치하는 콘텐츠를 발견하면 완료 정리를 복구한다.
- 완료 검증 후 정리 실패 메시지를 분리한다. 정리가 끝나야 새 홈으로 이동한다.
- 저장 잠금 해제 후 프레임을 반영하고 새 HomePage를 만들어 모든 교체 경로에서 홈을 최신화한다.
- 홈 조회 generation과 mounted 검사를 추가해 오래된 응답·dispose 이후 갱신을 방지한다.
- SQLite add는 transaction 안에서 같은 ID 콘텐츠 충돌을 검사한다. prefs도 같은 규칙을 사용한다.

## 데이터·범위
