# 너랑나랑 CI·DI 적용 1차

기준: 사용자 업로드 NN_Refactor_Review_20261022_184718.zip + 검증 완료한 1차 모듈 리팩터링.
이 문서는 앱 전체 DI 완료나 GitHub CI 실제 실행 성공을 선언하지 않는다.

## 변경 범위
- CompletionActions에 CompletionRecoveryContext와 clock 주입을 추가한다.
- 기존 CompletionActions(store) 호출은 유지된다. 기본 어댑터가 원래 저장소를 호출한다.
- 기본 의존성은 생성자에서 전역 저장소를 즉시 읽지 않고, 필요한 메서드 호출 시 해석한다.
  저장소 초기화 전 saveEdit/saveNew를 사용하던 기존 테스트와의 호환성을 보존한다.
- 완료 저장소는 기존 CompletionEditingStore 주입을 그대로 사용한다.
- 은혜 임시기록 읽기/정리, 문답 정리, 이전 완료 사본 정리, 이전 복구 기록 작업을 명시적 경계로 감싼다.
- UI·교재 문구·SQLite/SharedPreferences 저장 형식·스키마·서명 시각·삭제 tombstone 정책은 변경하지 않는다.
- 화면 전체·GraceConflictRecovery·다른 저장소의 전역 참조 제거는 후속 작업이다.

## 새 테스트 10개
외부 저장소/플러그인/SharedPreferences mock/initializeStorage 없이 각 테스트가 메모리 대역을 소유한다.
1. 복구 대기 저장 실패 시 commit 미실행 및 다른 완료 기록 보존.
2. 완료 저장 실패 시 재시도 원문/ID/주입한 시도 시각 보존.
3. 수정은 저장됐으나 응답이 유실된 경우 실제 내용 확인 후 성공 처리.
4. 수정 commit 실패 시 기존 내용과 대기 수정 둘 다 보존.
5. 완료 저장 후 문답 정리 실패 시 은혜 원문을 남기고 재시도에서 중복 없이 정리.
6. 은혜 정리 실패 후 재시도해도 기록/서명/완료 시각과 개수 유지.
7. 동시 두 서비스의 저장소와 임시기록이 서로 간섭하지 않음.
8. 이전 사본 정리 실패 시 후속 은혜/레거시 삭제 금지.
9. 다른 ID 정리 시 무관한 은혜 기록 보존 및 호출 순서.
10. 이전 복구 재시도는 주입 시각을 사용하고 기존 완료/서명 시각 보존.

기존 SQLite·SharedPreferences 계약 테스트는 그대로 필요하다. 메모리 대역이 실제 DB 트랜잭션을 증명하지 않는다.

## CI
파일: .github/workflows/nn-ci.yml, tool/Invoke-NN-CI.ps1.
GitHub push / pull_request / 수동 workflow_dispatch에서 실행한다.
- Windows 실행기로 사용자 환경과 맞춘다. Flutter 3.47.4 stable 고정.
- lockfile 강제 적용. SDK 버전 다운로드 실패 시 임의 최신/구버전으로 대체하지 않는다.
- 분석 → 전체 PC 테스트와 커버리지 → seed22022 순서 변경 재검사.
- 테스트 job 통과 후 별도 job에서 Java21·디버그 APK 빌드. 설치/배포/앱 데이터 접근 없음.
- 검사 로그·커버리지 합계·LCOV·범위 요약을 14일 보관.
- 예전 LCOV를 삭제한 뒤 새 테스트에서 생성된 결과만 집계. 0줄/잘못된 합계는 실패.
- 커버리지 임계치는 아직 고정하지 않는다. 동일 CI 환경 첫 통과 값을 확인한 후 결정한다.
- 보고서에는 Android SQLite·OS 강제 종료·출시 서명을 NOT_RUN으로 명시.
- job 시간제한, 같은 브랜치 이전 실행 취소, 읽기 전용 contents 권한, checkout credential 미보존.
- 공개 PR에서도 서명 키/개인 데이터/서비스 토큰 없이 실행한다. 개인 테스트 fixture를 커밋하지 않는다.
- Android 실환경 검사는 기존 Test-NN-Safe Device와 Test-NN-Lifecycle에서 수행한다.

## GitHub 활성화
패키지 적용만으로 GitHub에서 실행된 것은 아니다. 사용자 PC 최신 파일을 현재 브랜치에 커밋·push해야 한다.
현재 브랜치/변경 파일을 확인하고 아래 이번 파일만 선택적으로 추가한다. git add .를 사용하지 않는다.

```
git status --short
git branch --show-current
git remote -v
```

1차 모듈 리팩터링이 아직 미커밋이면 그 파일도 함께 커밋해야 한다.
이번 새 main.dart가 독립 모듈 import를 사용하므로 main.dart만 올리고 모듈 파일을 빠뜨리지 않는다.
앱 assets와 Android 프로젝트도 저장소에 추적되어 있어야 CI APK 빌드가 가능하다.
GitHub Actions에서 NN CI의 두 job 통과를 확인한다.
main 보호는 Settings → Rules → Rulesets/Branches에서 해당 브랜치에 적용하고,
Analysis and tests, Android debug build를 필수 검사로 지정한다.
이 규칙은 workflow 파일 자체로 설정되지 않는다. 첫 실행 후 실제 표시된 검사 이름을 선택한다.
직접 push 허용 여부는 기존 협업 방식에 맞춰 설정한다. CI는 자동 병합/배포하지 않는다.

## 검증 근거와 한계
로컬 수행: Dart 구문 트리, 기존 메서드 본문에서 의존성/시각 교체 이외 변경 여부,
PowerShell 구문 및 설치/복원/충돌/오류 전달 모의 검증, YAML job/단계 구조 검사.
환경: Linux PowerShell7. Windows5.1 및 GitHub Actions 실행은 NOT_RUN.
Flutter SDK가 없어 실제 Dart 타입 분석/테스트/APK 빌드는 NOT_RUN.
설치 도구가 사용자 PC에서 안전 Quick(분석·전체 PC 테스트)와 APK 빌드를 실행한다.
이후 필요하면 CI 전용 Tests 모드를 로컬 실행해 lockfile/coverage/shuffle도 확인한다.
과거 181개/기기검사 PASS를 이번 변경 검증으로 대신하지 않는다.
성능 측정은 사용자 요청에 따라 보류. 속도 향상/메모리 감소를 주장하지 않는다.
